# quorum-replicated-log-go

本地可运行的多数派复制式键值存储。多个副本运行在**同一进程**内，
用内存方法调用模拟网络、用文件 WAL 模拟持久化、用显式的崩溃/分区
接口模拟故障，从而在单机上复现真实集群的持久化、故障恢复与并发
写入语义。仅依赖 Go 标准库。

## 复制与提交语义

- **单领导者 + 任期**：`Cluster.Elect(id)` 以高于所有现存任期的新任期
  发起选主，获得多数票者成为领导者，并立即提交一条当前任期的 noop
  日志以确认领导权。
- **多数派提交**：客户端写入（`Replica.Propose`）先在领导者本地 WAL
  持久化，再复制到所有可达副本；只有**多数副本持久化确认**后才推进
  提交索引、应用到状态机并对外可见。提交顺序与持久化顺序一致。
- **可区分的拒绝原因**（均可 `errors.Is` 判定）：
  | 错误 | 含义 |
  |---|---|
  | `ErrNotLeader` | 目标是跟随者，或领导者在复制期间发现更高任期已下台 |
  | `ErrNoQuorum` | 可达副本不足多数派，写入被拒绝且不会应用 |
  | `ErrStaleTerm` | 旧领导者的复制请求携带过期任期，被跟随者拒绝 |
  | `ErrLogMismatch` | 日志前缀不一致，领导者回退后重试补齐 |
  | `ErrUnconfirmedRead` | 领导者未在当前任期提交过日志，无法确认最新状态，拒绝读取 |
  | `ErrCrashed` | 副本处于崩溃状态 |
- **旧写入失效**：领导者更替后，旧领导者凑不齐多数派（`ErrNoQuorum`），
  其复制请求被新任期跟随者以 `ErrStaleTerm` 拒绝并迫使其下台；
  旧任期未提交的日志会被新领导者的复制截断覆盖。
- **读取一致性**：仅领导者服务读取，且必须已在当前任期提交过日志，
  否则返回 `ErrUnconfirmedRead`；跟随者读返回 `ErrNotLeader`。
  已提交数据的读取不会返回旧值。
- **重试去重**：命令携带 `(ClientID, Seq)` 幂等键，状态机对每个客户端
  只应用单调递增的 Seq，超时重试返回缓存结果、不重复应用。
- **并发提交**：领导者在单把互斥锁下完成"分配索引 → 持久化 → 复制"，
  并发写入产生确定的全局顺序，各副本日志逐条一致、状态最终收敛。

## 持久化与恢复保证

- **WAL 格式**：`[uint32 长度][uint32 CRC32][gob(Entry)]`，每条记录
  写盘后（可选）fsync，提交顺序即落盘顺序。
- **残缺尾部处理**：恢复时从头扫描，遇到长度非法、CRC 失配或截断的
  记录，立即将文件**截断到最后一条完整记录**，残缺数据绝不进入内存
  日志、绝不静默应用。
- **元数据**：任期、投票、已提交索引通过 临时文件 + rename + fsync
  原子落盘（`meta.json`）。
- **崩溃恢复**：重启后重放 WAL 中 `≤ commitIndex` 的已提交记录；
  状态机按索引严格单调推进，重复回放同一条记录是 no-op，不改变
  状态、不产生计数膨胀；未提交的尾部记录不会被应用。
- **追赶与收敛**：领导者按各跟随者的匹配索引增量同步缺失日志，
  崩溃重启或分区恢复的副本会在后续复制中补齐并收敛。

## 关键配置项

```go
quorum.Config{
    ReplicaIDs: []string{"r1", "r2", "r3"}, // 副本列表，多数派 = n/2+1
    Dir:        "/path/to/data",            // 数据根目录，每副本一个子目录
    Fsync:      true,                       // 每次写盘 fsync（崩溃语义保证）
}
```

故障注入接口：`Crash(id)`（进程崩溃）、`Restart(id)`（从磁盘恢复）、
`Isolate(id)` / `Heal(id)`（网络分区与恢复）。

## 本地验证

```bash
# 全部单测（每个用例打印输入与判定依据）
go test ./quorum/ -v

# 竞态检测
go test ./quorum/ -race -count=2

# 端到端演示：选主 → 多数派提交 → 无多数派拒绝 → 崩溃恢复 → 收敛
go run ./cmd/kvdemo
```

测试覆盖：崩溃重启恢复、WAL 尾部残缺与 CRC 损坏、多数派之外的写入、
旧领导者失效写入、客户端重复重试、并发提交的确定顺序与最终收敛、
分区恢复后的追赶。
